# Phone source planner: recap of today's lanes and the redesign (phase 6)

Draft 1, 2026-09-28 night. Input: `recap/RECAP.md` (every source x category x network, generated by
`recap/build_recap.py` from the harness and in-app results), `DESIGN.md` (sections 3.0-3.3), the
engine code at MediaServiceCore c4de5a00 + the uncommitted phase 5 / walk-role work. Scope: the
phone's /player walk (`sPreferNoPotClient` on). TV / upstream behaviour stays byte-identical: the
planner is a VOIDXDEV file and a switch, `VIDEO_INFO_TYPE_LIST` is untouched.

## 1. Recap: how the phone chooses a source today

The order is not written anywhere. It is upstream's ring (`VIDEO_INFO_TYPE_LIST`, WEB_EMBED
first), transformed by `buildVisitOrder` / `buildRequestVisitOrder` and eleven helpers and static
gates, then trimmed while walking. Printed from the code (throwaway test, 2026-09-28), after the
walk-time skips (`isSkippedClient`: TV_LEGACY, TV_EMBED, TV_SIMPLY always; TV_DOWNGRADED unless
signed in) and with WEB_EMBED last (uncommitted MMA flip):

| lane | order actually asked |
|---|---|
| signed out, normal | VISIONOS WEB WEB_SAFARI GEO MWEB ANDROID_VR ANDROID_REEL TV IOS WEB_EMBED |
| signed out, anon partition challenged | VISIONOS ANDROID_VR ANDROID_REEL TV IOS WEB WEB_SAFARI GEO MWEB WEB_EMBED |
| signed out, recovery after a VISIONOS 403 | WEB WEB_SAFARI GEO MWEB ANDROID_VR ANDROID_REEL TV IOS WEB_EMBED (VISIONOS is gone: it is off-ring) |
| signed in, normal | TV_DOWNGRADED TV VISIONOS ANDROID_VR ANDROID_REEL WEB WEB_SAFARI IOS GEO MWEB WEB_EMBED |
| signed in, TV_DOWNGRADED quarantined | TV VISIONOS TV_DOWNGRADED ANDROID_VR ... WEB_EMBED |
| signed in, both heads quarantined | same as signed out, normal |
| signed in, recovery after TV_DOWNGRADED 403 | VISIONOS WEB WEB_SAFARI GEO MWEB TV IOS TV_DOWNGRADED ANDROID_VR ANDROID_REEL WEB_EMBED |
| bot wall on this network | BotWallBook's plan: account route (TV_TIZEN) + one anonymous probe per interval |
| live (answer says live) | the walk goes on only to live-DASH candidates (ANDROID_VR) holding the HLS answer |

Dynamic rules applied while walking (in `firstPlayable`): live-DASH skipping; the bot-wall
account-route insertion; the anonymous-TV_TIZEN-after-refusal insertion (switch, off);
`UnplayableConsensus` (needs a server-confirmed signed-in witness, so it never ends a signed-out
walk); the bot-check walk-on / trip rules (lone challenge amid refusals discounted, c4de5a00); the
45 s walk budget; transport-down after 2 no-response attempts. Per-attempt budgets:
account route and authenticated head 15 s, web-pot clients 20 s, others 7 s.

Other state that shapes the order: `mActualInfoType` (the last winner, inserted second by
`buildVisitOrder` - after a kids video won by TV_TIZEN, every later walk asks TV_TIZEN in the
middle of the ring); the persisted winner hint (restored only for in-ring, non-web, non-skipped
clients: VISIONOS never qualifies, ANDROID_REEL / IOS / TV do - a cold start after an odd video
begins on the odd client); the recovery cursor.

What this costs, measured (in-app, Pixel 9, LTE, 2026-09-28): a made-for-kids video walks 9 clients
(~4-6 s) to reach WEB_EMBED, the only one of them that serves it, and on the released build (WEB_EMBED
skipped) TV's "not a bot" answer then armed the bot-check circuit and blocked the next normal video
without a request (repro-botcircuit-v4). Seven of the ten are dead for every category we measured
(section 2).

## 3. The planner

Draft 2, after a Codex astra adversarial review (`review/codex-planner-astra.md`): signed-out only,
TV_TIZEN only after a refusal, recovery order fixed, an auth-flag misclassification corrected in
planned walks.

`PhoneSourcePlanner` (VOIDXDEV, `videoinfo/V2/sources/`), pure and unit-tested, computes the order of a
signed-out phone walk (`sPreferNoPotClient`, no forced client, not walled) behind
`VideoInfoService.setPlannerEnabled` / `debug.arc.planner=1`. The walk loop, BotWallBook, the
TV_TIZEN refusal rule, live-DASH skipping, consensus, the bot check, budgets and transport rules stay
in `firstPlayable`. Signed in, nothing changes: there is no signed-in measurement at all.

### 3.1 The signed-out lane

1. **VISIONOS** - one request for almost everything.
2. **TV_TIZEN, without the account - only after an anonymous refusal** (UNPLAYABLE from a non-web
   client, no live signal, no wall, TV_TIZEN not route-failed on this attachment/video): the existing
   rule (`setAnonTizenAfterRefusal`), with its guards and the speculative 7 s budget. Made-for-kids
   videos (device LTE: 11/11). A timeout, an age gate or a removed video never reaches the TV family.
3. **WEB_EMBED** (embed identity, pre-roll wait honoured, HLS when switched on) - age-restricted
   embeddable, kids when TV_TIZEN fails.
4. **ANDROID_VR** - live DASH (its VOD media hits the deep-range 403 wall: not a real fallback).
5. Unproven tail: IOS, ANDROID_REEL, MWEB, WEB, WEB_SAFARI. Out: GEO, TV 7.x, the TV fallback clients.

Recovery (the watched video's reload after a media 403): the failed client moves to the END instead
of vanishing (VISIONOS used to vanish, so its recovery landed on SABR-only or 60-second web clients),
after the challenged-web demotion so nothing moves in behind it. Anonymous web challenged: web
clients last. Bot wall: BotWallBook's plan (unchanged). Live: unchanged. Winner hint / last winner:
still written and still used for recovery blame, not for the order.

Still active in planned walks (not replaced): `isSkippedClient` (the planned list holds no skipped
client; `setSkipWebEmbed` must stay off), the live-DASH skip (needs a held playable live answer), the
45 s walk budget, transport-down.

### 3.2 Switching inside a walk (failure classes, DESIGN 3.0)

| answer | class | next |
|---|---|---|
| OK, usable adaptive (or HLS / SABR accepted) | playable | stop |
| UNPLAYABLE, anonymous non-web, no live signal | client-refused | TV_TIZEN next (once, guarded), then the lane |
| LOGIN_REQUIRED age gate | restricted-age | the lane (WEB_EMBED is next); TV_TIZEN not asked |
| live signal with a held playable answer | live | live-DASH candidates only (unchanged) |
| explicit "not a bot" | bot-challenge | BotCheckWalkState / BotWallBook (unchanged) |
| no response | transport | transport-down after 2 (unchanged) |
| OK, SABR-only, no accepted delivery | delivery-unsupported | the lane |
| ERROR / terminal reason | content-terminal | signed in: consensus as before; signed out and planned: the same allowlisted reason from all three visitor identities (web session, app, embed page) settles it (a removed video: the 4th request instead of the 8th) |

Auth flag: the app marks an auth-capable client's answer authenticated whether or not an account went
with it. Signed out, that made TV_TIZEN's challenge read as the account route failing, its refusal as a
signed-in witness, and skipped the guest subtitle enrichment. Planned walks correct it per answer. The
ring keeps the old flag: corrected there, TV 7.x's lone kids "not a bot" would become anonymous wall
evidence, and two kids videos in 10 min would wall the attachment.

### 3.3 Switching during playback (ErrorFixerController)

Unchanged except the recovery order. The readiness gate keeps a startup 403 of an ad-bearing answer
from reaching route recovery.

### 3.4 What is retired once the planner is the default

The phone stops calling `setAnonTizenAfterRefusal` (the planner implies the rule) and the
`debug.arc.anon_tizen` switch goes. `setWebEmbedLast`, the helper stack in `buildRequestVisitOrder` and
the ring stay: they are the signed-in walk, and the signed-out rollback (`debug.arc.planner=0`) for one
release.

### 3.5 Follow-ups (not in this change)

- An episode-wide recovery budget (failed-source history and a request cap per playback episode;
  ErrorFixer's counters reset on play/progress) and honouring BotWallBook route benches outside a wall.
- The general auth-flag fix, together with discounting a lone challenge amid content refusals as wall
  evidence.
- Completing the SABR path for SABR-only answers (server backoff, readiness).
- Signed-in measurement (needs a test account; never the owner's).

## 4. Acceptance before the switch becomes the default

Per network (Wi-Fi and LTE), planner on vs off with the same build (astra's matrix, adapted):

| run | videos | opens per video |
|---|---:|---|
| kids | 5 | 3 on + 3 off, 150 s + seek |
| ordinary controls (multi-audio, music, long, Shorts, 4K) | 5 | 1 on + 1 off |
| embed-disabled, age embeddable, age not embeddable, live, replay | 1-2 each | 1 on + 1 off |
| upcoming, removed, private | 1 each | 1 on + 1 off |
| WEB_EMBED reached / readiness (forced) | 10 | 3, to >=15 ad-bearing answers |
| kids -> ordinary in one process | 3 pairs | 1, keep-process |

Block on: any reproducible playback regression; a shortened ad wait; a reselected benched route; a
recovery beyond its budget; a failure that poisons the next ordinary open; any new challenge (stop and
investigate). Request budgets per scenario instead of "never more": a healthy open 1; kids 2 (3 if
TV_TIZEN refuses); age embeddable 2; removed 4; nothing serves <= 8.
